# 占星術リーディング補助アプリ 企画書
 
**作成日：** 2026年6月21日
**ステータス：** 企画確定（実装フェーズ移行前）
 
---
 
## 1. 背景・前提
 
ゆき氏（占星術師）が、これから本格的に始める占星術活動を支援するために開発する、個人専用のリーディング補助ツール。
 
### 開発アプローチ
 
```
自分自身が使う → 効果を実感できれば → サービス化を検討
```
 
最初から多数のユーザーを想定した製品設計ではなく、**まず自分自身のワークフローを最適化すること**を最優先とする。これにより、机上の要件定義ではなく実際の使用を通じて本当に必要な機能が明確になる「ドッグフーディング型」の開発を行う。

## 3. 解決したい課題
 
ゆき氏自身のリーディング実務において、以下の業務に最も時間がかかると想定されている（優先度順）：
 
1. **チャートを見ながら解釈メモを取る**（最大のボトルネック）
2. **クライアントにテキストで届ける**
3. **解釈内容を文章にまとめる**
4. クライアント情報・質問内容の確認
5. チャートの生成・確認
加えて、以下の構造的な課題も存在する：
 
- チャート生成・メモ・クライアント管理が**別々のツールに分断**されている
- 過去に読み解いた星座・天体・アスペクトの解釈を、再度別のクライアントで参照する仕組みがない
- 同じ天体配置に対する解釈の蓄積が、個人の記憶や紙のメモに依存している
---
 
## 4. コアバリュー（企画の核）
 
> **占星術師の頭の中にある知識と文脈を、アプリが一本化し、資産として育てていく**
 
具体的には3つの軸で構成される：
 
### 4-1. チャートとメモの統合
チャートデータ（天体・ハウス・アスペクト）を構造化データとして保持し、リーディング中にメモを天体に直接紐づけられる。
 
### 4-2. クライアント管理とセッション履歴
クライアントごとに、チャート情報とセッションの記録を時系列で蓄積する。
 
### 4-3. 解釈辞書（ナレッジベース）
「金星×双子座」のように、天体とサイン／ハウス／アスペクトの組み合わせ単位で、自分自身の解釈を蓄積する独自辞書。使うほど育つ知識資産であり、将来的に解釈データそのものを活用する可能性も見込む。

## 5. リーディングスタイル・利用想定
 
| 項目 | 内容 |
|------|------|
| リーディング手法 | ネイタル・トランジット・シナストリーなど複数を組み合わせる |
| セッション形式 | テキストチャット・メッセージ中心 |
| 利用環境 | PC（メイン）＋ 外出先でのスマートフォン利用 |
 
テキストベースのセッションは会話記録が自然に残るため、アプリのデータ構造（メモ・履歴の蓄積）と相性が良い。
 
---
 
## 6. データ構造の基本方針
 
機能設計における最も重要な決定事項。
 
```
クライアント
│
├── チャートデータ（1つ・永続）
│   ├── 天体・ハウス・アスペクト情報
│   └── 天体別解釈メモ（チャートに対する解釈。参照・上書き可能）
│
└── セッション記録（複数・都度追加）
    └── その日に話した内容・全体的な気づき（日誌的な記録）
```
 
- **チャート解釈メモ**：クライアントのチャートそのものに対する解釈。セッションを重ねるごとに深まり、上書き・更新されていく一つのデータ。
- **セッション記録**：個々のセッションで何を話したか、その時の気づきを残す独立した記録。セッションごとに蓄積される。
この2つを明確に分離することで、「チャートの理解を深める」作業と「クライアントとの対話の履歴を残す」作業を役割分担できる。
 
### 解釈辞書との連携
 
チャート解釈メモは、ゆき氏が運用する**解釈辞書**（天体×サイン、天体×ハウス、アスペクトの単位で構成される独自ナレッジ）と双方向に連携する。
 
- セッション中に該当する組み合わせの辞書エントリーを即座に参照できる
- メモの内容を辞書エントリーとして保存・登録できる（セッション中・セッション後どちらでも可能）

## 7. 機能スコープ
 
### MVP（最初に実装する機能）
 
| 機能 | 内容 |
|------|------|
| クライアント管理 | 基本情報（氏名・生年月日・出生時刻・出生地等） |
| ネイタルチャート表示 | 天体・ハウス・アスペクトの計算・表示 |
| チャート解釈メモ | 天体に紐づけて記録、参照・上書き可能 |
| セッション記録 | セッションごとの独立した記録 |
| 解釈辞書 | 天体×サイン／ハウス／アスペクト単位の解釈データベース |
| 辞書のセッション内参照・登録 | リーディング中にその場で参照・保存 |
 
### Should Have（早期に追加したい機能）
 
| 機能 | 内容 |
|------|------|
| メモ→テキスト出力 | クライアント送信用の文章として整形・出力 |
| 複数チャート表示 | トランジット・シナストリー等の並列表示 |
 
### Nice to Have（将来的に検討）
 
| 機能 | 内容 |
|------|------|
| 複合条件の解釈 | 天体×サイン×ハウスなどの複合的な解釈データ |
| 解釈データのエクスポート・商品化 | 蓄積した解釈辞書の外部活用 |
| AI文章化サポート | 解釈メモの自動文章化（フェーズ1では非搭載） |
 
> **AIに関する方針：** フェーズ1ではAIによる自動解釈・文章化機能は搭載しない。まずツールとしての堅牢さ・実用性を確立し、後から追加できる設計にしておく。

## 8. 画面構成（5画面）
 
UXモックアップにて確認済み。
 
| 画面 | 役割 |
|------|------|
| ① ダッシュボード | 概況確認・最近のセッション一覧 |
| ② クライアント一覧 | クライアントの検索・絞り込み（太陽・月・ASCタグ表示） |
| ③ クライアント詳細 | 基本情報＋セッション履歴の確認 |
| ④ セッション画面（コア画面） | チャート表示＋天体別メモ＋全体メモの記録 |
| ⑤ 解釈辞書 | 解釈データの参照・編集・セッションとの紐付け確認 |
 
セッション画面（④）が最も使用頻度が高く、設計上の中心となる。
