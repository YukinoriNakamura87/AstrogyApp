## 2. 最初に通す縦串（MVPの中の最小スコープ）
 
> **クライアント登録フォーム → ネイタルチャート計算（Kerykeion） → チャート確認 → 解釈メモ作成・保存**
 
企画書のボトルネック分析（「チャートを見ながら解釈メモを取る」が最大の課題）に直接対応する、最小だが実用可能な一連の流れ。
 
### スコープの線引き
 
| 項目 | 最初の縦串に含むか | 理由・備考 |
|------|------|------|
| クライアント管理 | 登録フォームのみ | 一覧・検索は後回し |
| チャート種別 | ネイタルのみ | トランジット・シナストリーは後続フェーズ |
| 解釈辞書との連携 | 含めない | メモは単体保存のみ。辞書参照・登録は後続フェーズ |
| セッション記録（独立記録） | 含めない | `sessions` テーブルは型だけ用意してもよいが、機能としては後続 |
| ダッシュボード・一覧画面 | 含めない | 後続フェーズ |

## 3. フェーズ別ロードマップ
 
### Phase 0: 開発環境構築
 
- Docker Compose（frontend / backend / db の3コンテナ構成）
- PostgreSQLの初期設定・永続化ボリューム設定
- 各コンテナのDockerfile・ホットリロード設定
- `.env` 管理方針の決定
**完了条件：** `docker compose up` で3コンテナが立ち上がり、空のFastAPI・空のNuxtにブラウザからアクセスできる
 
---
 
### Phase 1: バックエンド基盤（最小スコープ）
 
1. **DBスキーマ・マイグレーション**
   - `clients`（基本情報のみ：氏名・生年月日・出生時刻・出生地）
   - `charts`（ネイタルのみ）
   - `chart_interpretation_memos`
   - ※ `sessions`, `dictionary_entries` はテーブル定義のみ先行させてもよい（後続フェーズで使用）
2. **Kerykeion連携**
   - 出生情報からネイタルチャートを計算する最小限のエンドポイント
   - 計算結果のDB保存（再計算不要のキャッシュ設計）
3. **CRUD API（最小）**
   - `POST /clients`（登録のみ、一覧APIは後回し）
   - `GET /clients/{id}/chart`（計算 or キャッシュ取得）
   - `GET, PUT /clients/{id}/chart/memos`
**完了条件：** Swagger UI（FastAPI自動生成）から上記エンドポイントを叩いて、正しくデータが返ってくる
 
レビューはさらに以下の単位に分割可能：
- DBスキーマ
- Kerykeion連携
- CRUD一式
---
 
### Phase 2: フロントエンド実装（最小スコープ）
 
- クライアント登録フォーム（モックアップ②一覧・③詳細は実装しない／最小限）
- セッション画面（コア画面）：チャート表示＋天体別メモ入力・保存
- バックエンドAPIとの結合
- レスポンシブ対応（特にセッション画面を優先的に検証）
**完了条件：** 実際にゆき氏自身のデータで、クライアント登録 → チャート計算 → メモ記録、の一連の流れが動く
 
---
 
### Phase 3: 縦串完成後の拡張
 
- クライアント一覧・検索（モックアップ②の本実装）
- トランジット・シナストリー等の複数チャート対応
- 解釈辞書との連携（チャート解釈メモからの参照・登録）
- セッション記録（独立記録としての `sessions` 機能本実装）
- ダッシュボード（モックアップ①）
---
 
### Phase 4: 結合・調整（将来）
 
- 認証（個人利用フェーズでは簡易方式を想定）
- 全体的なバグ修正・UX調整
- 実運用に向けた最終チェック
- （将来的に）PWA対応、サービス化検討
